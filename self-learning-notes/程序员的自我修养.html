程序员的自我修养——链接、装载与库

一、简介

1. 一些基本概念

计算机的三个关键部件：CPU、内存、IO控制芯片。

硬件和应用程序之间的中间层使得两者之间保持相对独立。

内存分配问题的解决方案：

  • 分段（segmentation）：把一段与程序所需要的内存空间大小的虚拟空间映射到某个地址空间，建立虚拟空间到物理空间的映射关系，解决地址空间不隔离和程序运行地址不确定的问题。
  • 分页（paging）：解决分段无法提高内存使用效率的问题，利用程序的局部性原理，把地址空间认为等分为固定大小的页（有些操作系统支持不同大小的页，但同一时刻只能选择一种大小）。

2. 线程与进程

定义：

线程（thread）：也叫做轻量级进程（lightweight process，LWP），是程序执行流的最小单元。由线程ID、当前指令指针、寄存器集合和堆栈组成。

进程（process）：由一个到多个线程组成，各个线程之间共享程序的内存空间（包括代码段、数据段、堆等）及一些进程级的资源（如打开文件和信号）。

线程调度：

在单处理器对应多线程的情况下，并发是一种被模拟出来的状态：轮流执行、快速切换，造成看起来在同时处理的假象。

线程调度中线程拥有至少三种状态：

  • 运行：线程正在执行——拥有一段可以执行的时间，被称为时间片（time slice）。
  • 就绪：线程可以立刻运行，但CPU已经被占用。
  • 等待：线程正在等待某一事件（I/O或同步）发生，无法执行。

线程调度的方法：

  1. 优先级调度（priority schedule）：线程拥有各自的线程优先级，优先级修改的方式有3种：
    • Windows下通过使用 BOOL WINAPI SetThreadPriority(HANDLE hThread, int nPriority)手动修改，Linux下通过pthread库实现。
    • 根据进入等待状态的频繁程度提升或降低优先级（频繁等待的称为IO密集型线程（IO bound thread），很少等待的称为CPU密集型线程（CPU bound thread），前者会更容易得到优先级的提升）。
    • 长时间得不到执行的线程会被提升优先级（避免饿死（starvation）的发生）。
  2. 轮转法（round robin）：各个线程轮流执行一小段时间。

线程安全：

原子（atomic） 操作：有些操作（例如自增++x操作）被编译为汇编代码之后不止一条指令，因此可能执行了一半就被调度系统打断。为了避免这种情况，将这种单指令的操作设置为原子操作以避免其被打断。

同步（synchronization）：同一时间只能有一个线程对同一个数据进行访问。

锁（lock）：通过锁的获取与释放控制其它线程等待而非运行，保证操作只有一个线程在进行。锁的常见种类如下：

  • 二元信号量（binary semaphore）：只有占用与非占用两个状态，适合只能被唯一一个线程独占访问的资源。推广形成的多元信号量（简称为信号量（semaphore））允许 N 个线程并发访问。
  • 互斥量（mutex）：与二元信号量类似，但信号量在整个系统中可以被A线程获取后由B线程释放，但互斥量要求只能由获取互斥量的线程释放相应的锁。
  • 临界区（critical section）：比互斥量更加严格的同步手段。临界区的作用范围仅限于本进程，但互斥量当中进程A创建互斥量，进程B试图获取该互斥量是合法的。
  • 读写锁（read-write lock）：有共享（shared）和独占（exclusive）两种获取方式。自由状态的读写锁可以由任意一种方式获取，并被设置为对应的状态；共享状态的锁可以以共享方式获取，但试图以独占方式获取必须等待所有共享状态的锁全部释放；独占状态的锁组织任何其他线程获取该锁。
  • 条件变量（condition variable）：作用类似于一个栅栏。线程可以等待cv，也可以唤醒cv。唤醒cv之后某个或所有等待此cv的线程都会被唤醒并继续支持。

可重入（reentrant）：一个函数被重入，表示这个函数没有执行完成，由于外部因素或内部调用，又一次进入该函数执行。可重入函数表面该函数被重入后不会产生任何不良后果。例如int sqr(int x) { return x * x; }是可重入的。可重入函数必须具有如下特点：

  • 不使用任何（局部）静态或全局的非const变量及其指针
  • 仅依赖于调用方提供的参数
  • 不依赖任何单个资源的锁
  • 不调用任何不可重入的函数

过度优化：有时合理使用锁也不能保证线程安全。一般有如下三种原因：

  • 编译器为了提高速度，将一个变量缓存到寄存器内而不写回。
  • 编译器调整操作变量的指令顺序。
  • CPU动态调度换序。

使用volatile关键字可以阻止编译器层面的过度优化，但无法阻止CPU调度换序。

一个著名的例子：Singleton模式的double-check

首先讲解double-check的作用：

  • 内层的条件判断为逻辑必须。倘若仅有外层，那么如果A和B同时通过外层检查后，A先获得锁、创建instance、释放锁，随后B拿到锁以后也会创建一个instance，造成内存泄漏。
  • 外层的条件判断为性能优化。倘若仅有内层，那么无论何时到达的线程都会调用lock()和unlock()，调用开销大。外层的if添加以后，仅有进度相近的线程（同时通过外层检查）才会调用lock()。

步骤如下：

  • 词法分析：将源代码程序输入到扫描器（scanner）当中，将字符序列分割成一系列的记号（token），一般分为关键字、标识符、字面量、特殊符号。
  • 语法分析：用语法分析器（grammar parser）对token进行语法分析，从而产生语法树（syntax tree）（采用上下文无关语法（context-free grammar）进行）。
  • 语义分析：用语义分析器（semantic analyzer）完成，来分析语句的静态语义（static semantic）是否合法，例如声明、类型匹配、类型转换等等，给语法树表达式标识上类型，插入相应的隐式转换节点。但它无法分析动态语义（dynamic semantic），即只有在运行期才能确定的语义是否合法。
  • 中间语言生成：采用源码级优化器（source code optimizer），通过将整个语法树转换成中间代码（intermediate code）对源代码进行优化。常见的中间代码为三地址码（three-address code），其形式为x = y op z。在此过程中会进行一些优化，例如把t1 = 2 + 6直接优化成t1 = 8，并将后续用到t1的部分全部代替为数字8（这样也能节省一个临时变量）。
  • 目标代码生成与优化：从编辑器前端转向编辑器后端，用代码生成器（code generator）将中间代码转化为目标机器代码，用目标代码优化器（target code optimizer）进行优化，例如选择合适的寻址方式、使用位移代替乘法运算、删掉多余的指令等等。

这时候出现了一个问题：如果程序中有些变量或函数定义在其它的程序模块当中，应该如何确定它们的地址呢？这就需要链接器对目标文件进行链接，在后续会提及。

链接：

链接是本书的主要内容，因此在此处先只作简单介绍。

链接的历史比编译更为悠久，它起源于程序在纸带上运行时的跳转指令。由于程序并不是一写好就永久不变的，因此每次跳转的目标指令位置调整之后，程序员都要相应重新计算跳转指令。这一过程叫做重定位（relocation）。

后来人们发明了汇编语言，用符号（symbol）来代表每个指令的含义，因此跳转指令就无需再因为程序的增删而相应修改了（因为调用的函数名【即符号】不会发生变化）。但在一个程序被分割成多个模块时，就需要进行模块间符号的引用，这个拼接过程就是链接。

从原理上讲，链接的工作就是把一些指令对其它符号地址的引用加以修正，这一过程主要包括了地址和空间分配（address and storage allocation）、符号决议（symbol resolution）和重定位等这些步骤。

假如存在一个全局变量var位于目标文件A里面，要在目标文件B中访问这个变量。在编译B的时候，编译器并不知道var的目标地址，所以编译器将对应指令的目标地址设置为0，等待链接器在将目标文件A和B连接起来的时候再将其修正。链接后修正地址的过程也被叫做重定位，每个要被修正的地方叫一个重定位入口（relocation entry）。

2. 目标文件有什么

常见格式

WindowsLinux
可执行文件.exeELF可执行文件
动态链接库.dll.so
静态链接库.lib.a

这张表格中的所有文件都是按照可执行文件格式（executable）存储的。Windows下为PE（portable executable），Linux下为ELF（executable linkable format），它们都是COFF（common file format）格式的变种。

ELF格式又分为如下四类：

  • 可重定位文件（relocatable file）：包含代码和数据，可以被用来链接成可执行文件或共享目标文件。
    • Linux的.o
    • Windows的.obj
    • 静态链接库
  • 可执行文件（executable file）：包含可以执行的程序，一般没有扩展名。
    • /bin/bash文件
    • Windows的.exe
  • 共享目标文件（shared object file）：包含代码和数据，可以在两种情况中使用。一是链接器可以将这种文件和其它的可重定位文件、共享目标文件链接，产生新的目标文件；二是动态链接器可以将几个共享目标文件与可执行文件结合，作为进程映像的一部分运行。
    • Linux的.so
    • Windows的.dll
  • 核心转储文件（core dump file）：进程意外终止时，系统可以将该进程的地址空间的内容及终止时的一些其他信息转储到核心转储文件。
    • Linux的core dump

存储方式

目标文件将代码、数据、链接时所需要的信息等按不同的属性，以节（section）的形式存储，也叫做段（segmentation）。常见的有如下几种分类：

  • 代码段（code section）：程序源代码编译后的机器指令。【程序指令】
    • .code或.text
  • 数据段（data section）：全局变量和局部静态变量。【程序数据】
    • .data：已初始化的上述变量，往往以小端字节序（little-endian byte order）存储，即应当在十六进制下两格两格倒着读数。
    • .rodata：只读数据：程序中的只读变量和字符串常量。
    • .bss：未初始化的上述变量。由于它们的默认值为0，所以给它们在.data中分配空间并且存放数据0是没有必要的。往往编译器优化会将初始化值为0的上述变量也放到.bss当中。但有些编译器不会讲全局未初始化变量放在.bss中，只预留一个未定义的全局符号，等链接成可执行文件后再在.bss中分配空间。

数据和指令分段的好处有：

  • 便于合理的权限设置：数据区域设置为可读写，指令区域设置为只读。
  • 提高CPU缓存（cache）的命中率。
  • 节省大量空间：当系统中运行着多个该程序的副本时，它们的指令都是一样的，所以内存中只需要保存一份改程序的指令部分，对于许多其它资源也是如此。例如Windows Internet Explorer 7.0运行起来后私有部分数据仅占总虚存空间的约13%。

3. ELF文件结构

文件头（header）

可以用readelf指令详细查看ELF文件内容，-h参数表示文件头：

文件头包含以下几个关键部分：

  • ELF魔数：在文件识别中，魔数是位于文件开头的一组固定字节序列，用于标识文件类型和格式。
    • 最开始的4个字节是所有 ELF 文件都必须相同的标识码，分别为0x7F，0x45，0x4c，0x46，第一个字节为ASCII码当中的DEL控制符，后面3个字节为ELF三个字母的ASCII码。几乎所有可执行文件格式的最开始几个字节都是魔数，操作系统在加载时会确认魔数是否正确，如果不正确会拒绝加载。
    • 第5个字节标识ELF文件类，0x01表示是32位的，0x02表示是64位的
    • 第6个字节是字节序，规定ELF文件是大端还是小端的
    • 第7个字节规定ELF文件的主版本号，一般是1
    • 后面9个字节ELF标准没有定义，一般填0
  • 文件类型：每个文件类型对应一个常量，系统通过该常量（而非文件的扩展名）判断ELF文件的真正类型，相关常量以“ET_”开头。
    • ET_REL的值是1，代表可重定位文件
    • ET_EXEC的值是2，代表可执行文件
    • ET_DYN的值是3，代表共享目标文件
  • 机器类型：表示ELF文件的平台属性，该常量代表该ELF文件能在哪些平台上使用，相关常量以“EM_”开头。（一共有6种，不一一列举了）

重定位表记录需要重定位的部分，它同时也是ELF的一个段，因此也会出现在段表的信息当中。

字符串表（string table）和段表字符串表（section header string table）

由于字符串的长度往往是不确定的，用固定的结构来表示比较困难。一种常见的方式是把字符串集中起来存放到一个表中，然后使用字符串在表中的偏移来引用字符串。例如该字符串表：

+0\0helloworl
+10d\0Myvariab

那么就能用偏移对应如下字符串：

1hello
6world
12Myvaribale

通过这种方式，在ELF文件当中引用字符串，只需要给出一个数字下标而不用考虑其长度。字符串表用于保存普通的字符串，比如符号的名字，它在ELF文件当中也以段的形式保存；段表字符串表保存段表中用到的字符串，比如段名。

4. 链接的接口——符号

可以用nm指令来查看ELF文件的符号表：

符号表中的符号一共有以下几类：

  • 全局符号：定义在本目标文件的全局符号，可以被其他目标文件引用。
  • 外部符号（external symbol）：在本目标文件里引用的全局符号，但没有定义在本目标文件中。【一种特殊的全局符号，也可以叫做全局符号】
  • 段名：这种符号由编译器产生，值即为段的起始地址。
  • 局部符号：只在编译单元内部可见的符号，对链接过程没有左右。
  • 行号信息：目标文件指令和源代码中代码行的对应关系。

对于链接而言，只有全局符号是重要的。

ELF符号表结构

ELF文件的符号表往往是文件中的一个段，段名一般为“.symtab”。其结构是一个Elf32_Sym的数组，每个该结构都对应一个符号，数组的第一个元素（下标为0的那个）为无效的未定义符号。

Elf32_Sym定义如下：

几个成员的定义如下：

  • st_name：符号名，包含了该符号名在字符串表中的下标；
  • st_shndx：符号所在的段。有以下几种情况：
    • 如果符号定义在本目标文件中，那么st_shndx表示符号所在的段在段表中的下标；
    • 如果符号不是定义在本目标文件中，又有如下三种情况：
      • SHN_ABS（0xfff1）：表示该符号包含了一个绝对的值，比如表示文件名的符号就属于这种类型；
      • SHN_COMMON（0xfff2）：表示该符号是一个“COMMON块”类型的符号；
      • SHN_UNDEF（0）：表示该符号未定义（定义在其它目标文件中）。
  • st_value：符号相对应的值。有以下几种情况：
    • 在目标文件中，且符号不是“COMMON块”类型的（即st_shndx不为SHN_COMMON），则该值表示该符号在段中的偏移（符号所对应的函数或变量位于由st_shndx指定的段，偏移st_value的位置）。这是最常见的情况，例如SimpleSection.o中的：
      • func1
      • main
      • global_init_var
    • 在目标文件中，且符号是“COMMON块”类型的，则st_value表示该符号的对齐属性。例如SimpleSection.o中的：
      • global_uninit_var
    • 在可执行文件中，st_value表示符号的虚拟地址，用于动态链接。
  • st_size：符号大小。对于包含数据的符号，这个值表示数据类型的大小。如果该值为0，代表符号大小为0或未知；
  • st_info：符号类型和绑定信息。低4位表示符号的类型，高28位表示符号绑定信息。符号绑定信息（Symbol Binding）以STB开头，符号类型（Symbol Type）以STT开头：
    • STB_LOCAL（0）：局部符号，目标文件外部不可见；
    • STB_GLOBAL（1）：全局符号；
    • STB_WEAK（2）：弱引用。
    • STT_NOTYPE（0）：未知类型符号；
    • STT_OBJECT（1）：数据对象，例如变量、数组等；
    • STT_FUNC（2）：函数或其它可执行代码；

特殊符号

链接的过程中会定义许多特殊符号，它们并没有在程序中定义，但可以直接声明并且引用。几个具有代表性的特殊符号如下：

  • __executable_start：程序起始地址，即程序的最开始的地址；
  • __etext或_etext或etext：代码段结束地址，即代码段最末尾的地址；
  • _edata或edata：数据段结束地址，即数据段最末尾的地址；
  • _end或end：程序结束地址。

符号修饰与函数签名

20世纪70年代以前，编译器编译源代码产生目标文件时，符号名与相应的变量和函数的名字是一样的，但这样容易产生命名冲突。于是UNIX规定，C语言源代码文件中的所有全局的变量和函数经过编译以后，相对应的符号名前加上下划线“_”；Fortran语言的源代码经过编译以后，前后都要加上下划线“_”。

但这种方式并没有从根本上解决符号冲突的问题，因此后来设计了名称空间（namespace）来解决许多符号冲突的问题。

现在整个环境发生了很大的变化，这样的冲突问题已经不是那么明显，因此Linux下的GCC编译器已经去掉了这种方式，但是在Windows平台下还保持着这样的传统。

函数签名修饰后名称（符号名）
int func(int)_Z4funci
float func(float)_Z4funcf
int C::func(int)_ZN1C4funcEi
int C::C2::func(int)_ZN1C2C24funcEi
int N::func(int)_ZN1N4funcEi
int N::C::func(int)_ZN1N1C4funcEi

这是一种常见的修饰方法，基本规则如下：

  • 所有符号都以“_Z”开头；
  • 每个名字前面的数字代表名字字符串的长度；
  • 对于嵌套的名字（在namespace或class中）的，后面紧跟一个“N”，再街上各个名称空间和类的名字，名字后面用“E”结尾；
  • 对于函数而言，它的参数列表紧跟在“E”的后面，int即为i，float即为f。

例如第4种函数签名可以拆分为：_Z + N + 1C + 2C2 + 4funcE + i。

弱符号与强符号

当多个目标文件中含有相同名字全局符号的定义，那么这些目标文件链接的时候将会出现符号重复定义的错误。例如两个目标文件中都定义了一个全局整形变量global，并且都将它们初始化，那么链接器在链接A和B的时候会报错。这种符号的定义被称为强符号（strong symbol）。

与之相对，有些符号的定义可以被称为弱符号（weak symbol）。对于C/C++语言来说，默认函数和初始化了的全局变量为强符号，未初始化的全局变量为弱符号。我们可以通过GCC的”__attribute__((weak))“来定义任何一个强符号为弱符号。

注意，强符号和弱符号都是针对定义来说的，不是针对符号的引用（extern）。

根据强弱符号的概念，链接器会按照如下规则处理与选择多次被定义的全局符号：

  1. 不允许强符号被多次定义，否则报符号重复定义错误；
  2. 如果一个符号在某个文件中为强符号，其它文件中为弱符号，那么选择强符号；
  3. 如果一个符号在所有目标文件中都是弱符号，那么选择其中占用空间最大的一个。

在引用的层面也有强引用和弱引用之分。强引用（strong reference）要求所有符号引用在链接成可执行文件时，都必须被正确决议，如果没有找到定义，链接器就会报符号未定义错误。
